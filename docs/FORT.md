# FORT and live reversible EF

FORT opens the complete verified capture history, including posts and replies, through its own navigation item. Home keeps its one chosen NOW. Each card retains its stable source ID, captured timestamp, Attention Span, exact original, checksum, exact text download and a route back into its thread. Duplicate titles never identify a source.

EF starts on. It groups exact quotes using the existing deterministic organizer, without saving a rewritten source or creating a commitment. Turning it off shows the exact stored string. The same reversible view updates while writing a new capture. Preview failure displays the original and leaves verified saving available. The display preference is kept locally when browser preferences are writable; it is not an inference about the person. No model, network request or helper runs.

The archive sorts actual timestamp instants newest first, with source ID as a stable tie-breaker. Numeric timestamp comparison handles timezone offsets correctly. It shows 50 cards at a time. Search scans all verified originals with a literal, case-insensitive substring, including punctuation and non-Latin writing. No wildcard expansion or title-based merging occurs. A source permalink opens a page around that stable ID even beyond the first 50 records. THREAD opens the existing root and selects a linked reply when appropriate.

An open archive is a reading snapshot. New arrivals offer an explicit refresh rather than replacing or reordering cards under the reader. Loading older captures appends to the current page. A source that becomes invalid loses its verified display immediately; its raw evidence remains in Engine Room recovery. A workspace reset clears the old archive DOM and draft projection, including when those views are hidden. Search, paging, opening originals and toggling EF never change NOW or infer that a thread was read.

There is no new persistence table or backup format. The archive reads existing verified captures; originals already travel in backup11 with their exact metadata and links. The existing 1,000-capture and 2,000,000-character workspace limits still apply. Paging bounds rendered cards; it is not evidence that every future entity or backup fits its full scale budget.

Native reference: RawDumps, core/rawArchive and core/ef. This is browser-specific paging over a verified immutable snapshot, rather than native SQL offset queries. Separate append-only corrections and transcripts are still pending. They must remain distinct from originals, have exact provenance and recoverable drafts, and must not silently retarget an existing source quote or commitment. Voice, invited help and the other gaps remain in PARITY.md. This slice does not complete the full EFFORT port.

Acceptance: `npm test`, syntax and publication checks, plus `PLAYWRIGHT_DIR=/path/to/playwright node scripts/archive-browser-check.mjs`. The browser suite supports `DEMO_BASE_URL` for the isolated hosted version. It exercises live EF and forced projection failure, exact drafts/downloads, 50-card paging, literal search, deep reply/thread routes, cross-tab reading stability, damaged-source recovery, offline reopening, reset clearing and a desktop 1,000-original capacity fixture. All fixtures are synthetic.
