# Separate source corrections and supplied transcripts

A correction appends a new record. It never overwrites an original post/reply, its timestamp, an existing commitment, or a self-reported completion receipt. A supplied transcript is a different record kind and is explicitly labeled as supplied text, not verified audio or provider output. No transcription service runs in this slice.

FORT EF follows native RawDumps precedence: latest correction, otherwise latest supplied transcript, otherwise original. Switching EF off returns the exact original. Search scans original and historical correction/transcript strings, including revisions beyond the first page. Thread roots keep their existing original writing; a separate disclosure exposes source history. Corrected projection offsets never select from an original. Exact source-linked revision proposal preparation is now implemented locally; REVISION_PROPOSALS.md and CURRENT_STATE.md retain its release status. Choosing an exact proposal detail remains separate from preparation.

Each sealed revision records a stable ID, original capture ID and text hash, kind, predecessor, exact text, explicit recovery acknowledgements and a timestamp. Each source/kind has one immutable chain. Matching retries reuse the accepted record across readback failure, tab races and backup restore. A new intentional revision has the current predecessor. Stale editing or effective-source bases refuse while preserving the writer's words. Explicit rebasing updates the base, not the draft text.

Drafts preserve source identity, predecessor, effective base, request ID, exact text and recovery choices. Programmatic resaving retains CRLF strings even though textarea display normalizes line endings. A failed save leaves the draft. A failed cleanup after an accepted write offers an exact cleanup retry and keeps the accepted text readable. Reset epochs fence pending writes, and draft recovery refuses to replace a nonempty correction/transcript composer. Explicit shell updates verify these drafts before reload.

Damaged revision groups are preserved as raw recovery. An older restored prefix doesn't become current while later history is missing. A replacement requires explicit acknowledgement of the affected raw records, shown in the editor with complete downloads. That acknowledgement travels through subsequent revisions in the same valid chain. It marks a new choice, not verification of damaged history. Missing original sources leave intact revision records independently readable and portable. Engine Room provides a paginated directory, including those orphaned histories. A primary-source repair race must not quarantine independently intact revision bytes.

Incoming history forks refuse atomically. Older backups don't erase newer source history. Optional revision-store failure leaves original capture and NOW usable, marks projection history unknown, disables revision writes and refuses an incomplete backup. Retoggling EF cannot resurrect a stale projection after storage failure or corruption. New saves require a verified original, even when historical revisions can be preserved independently.

Schema10 adds `sourceRevisions`. Backup12 imports versions1 through11. Complete backups include both histories, correction/transcript drafts, acknowledgement references and raw recovery. Restore merges before a single transaction, checks source/history/reset fences and verifies exact readback. Limits are4,000 revisions,4,000 UTF-16 units per text and4 MiB encoded history. Reaching a limit refuses new data rather than trimming old evidence.

The browser controls and persistence are new adaptation code. Native references are RawDumps, core/rawArchive and core/store's separate edit/transcript records. Checksums verify bytes and associations, not authorship or truth. Public fixtures are synthetic; no private phone, provider, personal ledger or external action is involved.

Verification uses `npm test`, full runtime syntax, the publication guard and `scripts/revisions-browser-check.mjs` with an existing Playwright installation. The script supports `DEMO_BASE_URL` and scoped `REVISION_WIDTHS`; the default is1440/390/320 plus isolated storage/source faults. CURRENT_STATE.md records actual executed gates. Voice capture, provider transcript provenance, bounded invited help and the rest of the full native map remain open.
